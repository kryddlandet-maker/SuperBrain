# Does the brain actually improve design?

No document validator or passing unit test proves design quality. Use this suite to test outcomes under controlled conditions. This release includes the protocol and briefs; it does not claim completed comparative model trials.

## Baselines

Compare the first AI Design Brain core at `441d80aaa51bc1dfcdcb8ccfc4197c8445981683`, the current combined legacy configuration, and SuperBrain. Pin exact content versions. Use the same Codex model and reasoning setting, project stack, asset set, tools, initial brief and practical time budget. Record actual loaded context. Do not compare a polished SuperBrain run against an unrefined baseline.

Use several independent runs per case if possible. Record time to first render, final route map, defects and human preference. Blind labels A/B/C reduce expectations from influencing review. Score each build separately before comparing; human reviewers should inspect mobile and interaction as well as screenshots.

## Cases

Use `cases.json`. These test quiet and expressive outcomes, actual routes, section flow, distinct typography, touch adaptation and preservation during small fixes. Create equal licensed/owned asset kits for each run. Allow the agent to ask questions, but answer consistently. A user-requested one-page campaign is included to prevent overcorrecting to a rigid multi-page rule.

## Evaluation

Hard failures: broken navigation/direct load, invisible essential content, fake business claims, unusable mobile/focus, broken submitted data or primary flow. Evaluate aesthetics separately on a 1–5 anchored scale:

| Dimension | 1 | 3 | 5 |
| --- | --- | --- | --- |
| Typography | Arbitrary, unreadable or generic | Coherent hierarchy | Distinctive and suited to content |
| Composition | Repeated skeleton | Varied but ordinary | Intentional scale/crop/rhythm |
| Continuity | Unmotivated slabs and gaps | Shared tokens | Flow with legible hierarchy |
| Business fit | Interchangeable look | Plausible | Specific to audience and evidence |
| Interaction | Gimmicky/broken | Works across inputs | Refined and conceptually relevant |

Do not let an average hide a hard failure. Capture reviewer reasons and actual observations, not just numbers. Report per-case and overall changes with failures and uncertainty. Only adopt new global guidance when repeated cases support it. A single impressive tech hero is insufficient.
