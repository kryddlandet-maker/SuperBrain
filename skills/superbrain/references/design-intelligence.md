# Design intelligence in three scopes

Use scripts/design.mjs with a real JSON brief. It returns a proposed design plan, routed reference IDs and reasons. Explicit direction, routes, motion and preferences win over the business starting profile. Profile recommendations are hypotheses, never verified business facts or an assurance of original design.

For quick-edit, record the exact defect and preserve the incumbent layout, data, typography and route map. Load only the affected chapter and accessibility/lifecycle dependencies. Do not generate a replacement brand system for a button fix.

For design-build, record audience, actual visitor action, available owned assets and verified content. Render the characteristic composition early. Validate the proposed palette, type roles, imagery and composition against that evidence. Revise an inappropriate profile starting point rather than repeating it. The engine includes separate starting profiles for salon, construction, technology, AI, automotive, portfolio, commerce, real estate, restaurant and operational CRM.

For creative-engineering, prototype the hard visual mechanic alongside useful content. Keep transform ownership, native input, direct routes, performance and reduced-motion alternatives explicit. Specialist graphics guidance is loaded when selected, not for every new site.

## From one short prompt to a working first version

Accept a compact request: subject, visitor goal, desired feeling and reference URLs/images are enough to start. Infer reversible details, state consequential assumptions briefly, and ask only for missing facts that block a real action. Do not make the user write a master prompt, select every effect or configure a dozen preferences. Work in one sustained loop: inspect the project and reference, pick a subject-specific composition, build the characteristic visual alongside working routes, inspect the actual browser, and refine the most visible defects before handing back.

For “rörliga rutor”, “aktiva animationer” or animated product demos, route to product-motion.md. Derive one input/action/consequence scene from the product task and select DOM/SVG or authored media from the actual visual. The generator exports a product-scene contract when requested; the agent still implements and verifies the scene. Scene planning and a single-page token preview are not a completed customer site.

Do not add all reference chapters to every prompt or promise one-pass perfection. Compare the same short request, assets, time budget and tools in controlled runs before claiming better design than another model. Public Claude skills are useful process evidence, not a complete account of Claude's internal capabilities. See docs/PRODUCT-MOTION-RESEARCH.md for the reviewed public sources and concrete differences.

Persist decisions in .ai/project/superbrain/project.json and design-system/MASTER.md using the generator's --out existing-project argument. Read these first when resuming. A project-owned journal should contain actual code paths, evidence and next action; never migrate its client-specific taste into reusable guidance. The generator checks previous hashes and unmanaged destinations before mutation. A locally edited file requires deliberate reconciliation, not force overwrite.
