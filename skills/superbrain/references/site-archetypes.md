# Distinct site archetypes

Use for portfolios, commerce, hospitality and other mixed briefs. An archetype describes visitor tasks, not a compulsory visual template. Derive routes from real content and avoid giving each business the same hero + cards + FAQ.

| Context | Useful route roles | Layout possibilities | Motion that may fit |
| --- | --- | --- | --- |
| SaaS / technology | Product, use cases, pricing, resources, contact | Immersive hero into legible product scenes; dense detail pages | Light fields, UI stories, continuing diagrams |
| Salon / wellness | Services/prices, people, approach, booking | Editorial imagery, readable service lists, warm portraits | Image reveal, gallery detail, responsive booking controls |
| Builder / architecture | Services, projects/detail, process, quote | Large project crops, specifications, material rhythm | Matching image transitions, honest comparison, diagram lines |
| Portfolio / studio | Work, project detail, practice, about/contact | Asymmetric project index into individually composed case studies | Grid continuity, selective distortion, kinetic short headings |
| Shop / product brand | Collection, product/detail, information, cart/checkout | Product-first imagery, specifications and usable variant selection | Rails, image zoom, real variant transitions, optional product 3D |
| Restaurant / hospitality | Menu, place/story, visit, reservations | Appetite-led imagery with readable menu and practical information | Image sequence, restrained reveal, light/material ambience |
| Professional services | Expertise, team, cases, insights, contact | Calm reading hierarchy, concrete proof and task-oriented navigation | Small state transitions and explanatory diagrams |

Use genuine assets and project facts. A restaurant menu is content, not a JPEG-only graphic. A shop needs actual variants, stock, currency, shipping information and real transaction behavior when that functionality is in scope; do not simulate success. A reservation link may connect to an existing authorized system. Do not build an AI-generated demo as if it is an operating business.

Inspect detail routes independently: a case study can use a wider opening image and narrower reading column; a product page needs image, choice and price proximity; a menu needs scanning and mobile legibility. Keep shared type, material and navigation while varying composition around the task.

The supplied collection illustrates visual/product/gallery techniques only. It is not a working store, restaurant booking system or full portfolio implementation. Pair the relevant visual recipe with the actual project architecture and flow.
